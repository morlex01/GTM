Find it. Write it. Ship it. Repeat.

The radar picks the topic. Opus 5.5 reads the sources and drafts. The pipeline puts it in front of the right people. What lands — replies, follows, booked calls — tells tomorrow's radar what to look for.

MORNING RUN

From radar to posted in one sitting.

08:00Press start. The 12h digest lands in Grok.
08:10Pick 3. Rising topics with primary sources.
08:15Research. Opus 5.5 reads the sources for each topic — links first, claims second.
08:40Draft. One post and one thread per topic from the templates.
09:00Fact-check. Every number against its link.
09:15Ship. Schedule it and log what went out.

The whole run fits before the first meeting. The research step is where Opus 5.5 earns its place: it reads long sources quickly and quotes them back with the link.

Weekly

  • Monday — run the 7D map and plan the long-form piece.
  • Friday — look at what landed and update the TRACK list.
House rule. If a number has no link, it doesn't ship.

GROK BOT

A morning trend radar for AI topics.

A bot in Grok that finds the freshest and most talked-about AI topics, so you post while they are rising — not after they peak. Claude writes the prompt; you paste it into Grok and press start.

Claude CodeOpusGPTGrokAnthropic
ModeWindowWhen
12Hlast 12 hoursevery morning — the default run
1Dlast dayevening wrap or a missed morning
7Dlast weekweekly map, long-form ideas

Why Grok for this

Grok reads X in real time, and X is where AI news usually breaks first. The radar lives where the signal is.

How it runs

  • On demand — you press start; no schedule to babysit.
  • Output stays in the Grok chat.
  • Each topic comes back with why it's hot, a post angle and links.

The PromptOpus 5.5 × GTM × Grok

THE PROMPT

A skeleton to paste into Grok.

ROLE    AI trend radar for an X creator
WINDOW  last 12h   (swap: 1d / 7d)
TRACK   Claude Code, Opus, GPT, Grok,
        Anthropic — plus anything new
        that is clearly breaking out
SOURCES X posts and news from the window
RANK    by velocity, not raw volume
RETURN  top 10, each with:
        - topic (one line)
        - why it's hot right now
        - one post angle for X
        - 2+ source links
RULES   no link, no claim
        say "unconfirmed" when it is
        skip anything older than WINDOW

Variants

  • 1D — same prompt, WINDOW last 1d, top 5.
  • 7D — RANK by staying power, top 10, group by theme.
  • Niche — swap TRACK for one company or one product.

Why each line is there

RANK by velocity keeps yesterday's big story from crowding out today's rising one. 2+ links lets you check a claim before it ships. "Unconfirmed" turns rumors into a flag instead of a fact.

LOG EVERY RUN

One hook, a full audit trail.

.claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write",
      "hooks": [{
        "type": "command",
        "command": "./scripts/log-run.sh"
      }]
    }]
  }
}
scripts/log-run.sh
#!/usr/bin/env bash
# one line per file the agent writes
payload=$(cat)
file=$(echo "$payload" | jq -r '.tool_input.file_path')
echo "$(date -u +%FT%TZ) $file" >> logs/runs.log
scripts/gate.sh · PreToolUse, matcher "Bash"
cmd=$(jq -r '.tool_input.command // ""')
if [[ "$cmd" == *send-sequence* ]] && [ ! -f approved.flag ]; then
  echo "Needs human approval first" >&2
  exit 2   # blocks the call
fi

After every Write, Claude Code pipes the call's details to your script. You get a timestamped list of every file the run produced.

Order of operations

Cache first — it is the biggest and safest saving. Move anything that can wait into Batch. Lower effort on mechanical rows. Only then think about a cheaper model for the simplest steps.

Opus 5.5 × GTM × GrokThe Skill

THE SKILL

Package the scoring step once. Run it every day.

A skill is a folder with a SKILL.md file: a name, a one-line description that tells Claude when to use it, and the steps. Supporting files sit next to it.

.claude/skills/icp-score/
├── SKILL.md
├── rubric.md
└── examples/good-fit.csv
# SKILL.md
---
name: icp-score
description: Score accounts 0-100 against
  our ICP rubric. Use for any account list.
---
1. Read the CSV the user passes
2. Per row: industry, size, signal + link
3. Score with rubric.md, one-line reason
4. Write scored.csv and a top-20 brief
$ claude -p "Score accounts.csv with the
  icp-score skill" --model claude-opus-5-5

Write the description like a trigger

Claude reads the description to decide when a skill applies. Say what it does and when to use it — "Use for any account list" does more work than "ICP scorer".

-p runs Claude Code headless — useful for scripts and scheduled jobs.

Hooks + MCPOpus 5.5 × GTM × Grok

HOOKS + MCP

Wire the agent into your stack — and put gates on it.

MCP: give it tools

The Model Context Protocol connects Claude to outside systems through servers: your CRM, an enrichment API, web search, a spreadsheet. Claude sees each server's tools and decides when to call them.

Hooks: your code, on a schedule

Hooks are shell commands Claude Code runs at fixed points in a session. They don't depend on the model remembering — they always fire.

EventFiresGTM use
PreToolUsebefore a tool callblock sends without approval
PostToolUseafter a tool calllog every file written
UserPromptSubmiton each promptattach today's date and ICP
SessionStartsession beginsload the latest digest
Stopagent finishespost a run summary

Connect only what the pipeline needs. Every tool you add is something the agent can call — read access first, write access when the step is proven.

The gate. A PreToolUse hook that exits with code 2 blocks the call and hands its message back to Claude.

Chapter 02

CLAUDE.MD

The memory your agent reads first.

Claude Code reads CLAUDE.md from your project at the start of every session. Whatever is there — who you sell to, how you score, what never to do — applies to every run without being repeated in the prompt.

# GTM agent — rules
## Who we sell to
- B2B SaaS, 20–500 employees, EU + US
- Buyer: Head of Growth or RevOps
## ICP rubric (0–100)
- Industry fit ............ 30
- Headcount fit ........... 20
- Fresh signal (<30 days) . 30
- Stack match ............. 20
## Voice
- One idea per line. No fluff.
- Mention the signal in line one.
## Never
- Send anything without approval
- Invent a fact. No source = cut it

Keep the rubric separate

CLAUDE.md can pull in other files with @path imports — e.g. @docs/icp-rubric.md. The rubric can then change weekly without touching the rules.

  • Short beats complete. Rules get followed; essays get skimmed.
  • Fix the file, not the run. When the agent gets it wrong, add one line here.

Chapter 03

GTM

Engineering the pipeline with Claude Code.

SignalEnrichScoreWriteShip

1 · Signal

Funding rounds, hiring, launches and leadership changes. Pull them in through MCP servers — web search, your CRM, job boards.

2 · Enrich

Turn every hit into one clean row per account: domain, size, industry, stack, the signal and its link. No duplicates.

3 · Score

Apply the rubric from CLAUDE.md, 0–100, with a one-line reason. Same rubric every run so weeks compare cleanly.

4 · Write

One opener per lead, built on the real signal. If the signal has no link, the lead goes back to Enrich.

5 · Ship

Push approved rows to the sequencer. A hook logs every file the agent writes, so each message traces back to its run.

Opus 5.5 × GTM × GrokWhat's New

WHAT'S NEW

Five changes to know before you migrate an agent.

1

Thinking is always on

Adaptive thinking can't be disabled. Budget for it instead of trying to switch it off.

2

Forced tool use returns an error

Let the model choose its tools. Pipelines that forced a specific tool call need a rewrite.

3

Effort sets the depth

The effort parameter controls how hard it thinks. Default is medium; lower it for bulk rows.

4

Text between tool calls moved

It now arrives in thinking blocks and is empty at the default display setting. If your app streams it as progress, set display.

5

Thinking blocks are bound

They are tied to the model and conversation that produced them — don't replay them into another model.

Migration checklist

  • Delete any code that tries to turn thinking off.
  • Replace forced tool calls with a clear instruction in the prompt.
  • Re-test streaming UIs with display set.
Also. The older computer_20251124 tool is not accepted on the Claude API. Minimum cacheable prompt is 512 tokens.

OPUS 5.5

The model under the hood of every workflow in this book.

Opus 5.5 is the first model of the Claude 5.5 family. Anthropic released it on September 22, 2026 and says it reaches the level of Claude Fable 5.1 on most work while keeping Opus pricing.

For a GTM engineer that shows up in three places: a context window big enough for whole account lists and CRM exports, cheaper tokens for batch scoring, and stronger agent behavior inside Claude Code — it delegates to subagents more effectively and runs its own self-checks.

COST + SPEED

Cheaper than the model it replaces — on every line of the bill.

Every token price is lower than on Opus 5. Anthropic also reports that typical workloads at default settings cost about 40% less to run, and that output generation is more than 30% faster.

Fast mode

A lower-latency Opus 5.5 in Claude Code and on the Claude Platform: up to 2.5× faster, priced at $8 input / $40 output per 1M tokens — exactly double.

Use it when a human is waiting — live calls, demos, debugging. Skip it for anything that runs while you sleep.

Batch API

Half price on input and output. Overnight ICP scoring, enrichment and first-draft openers all belong here.

Quick math. Re-reading 10M tokens of the same context costs $40 at the input price and $2 as cache reads.
